## Highlights

- **Brownian-bridge formulation** of the forward diffusion process that conditions endpoints on the user history representation, enabling autoregressive generation of the next item embedding.
- **Pretrain + warm-up** schedule: first pretrain a SASRec for item embeddings, then unfreeze them mid-training so the diffusion module starts from a well-shaped semantic space.
- **Unified PyTorch interface** for diffusion, Transformer, RNN, and VAE models — all share the same `forward(item_seq, tgt_seq) → (out_seq, last_item, aux_loss)` contract (see [Adding a New Model](#adding-a-new-model)).
- **One-click reproduction**: every table/figure in the paper is regenerated by a single shell script in `src/`.

## Environment Setup

We tested on Linux + CUDA 12.1 with the versions in `requirements.txt`.

```bash
# 1. Create a fresh Python env (Python ≥ 3.10 recommended)
conda create -n bbdrec python=3.10 -y
conda activate bbdrec

# 2. Install dependencies (PyTorch 2.1.2, NumPy 1.26.2, ...)
pip install -r requirements.txt
```

> **GPU note.** All shell scripts default to `cuda:0`. The multi-GPU launchers (`run_baselines.sh`, `reproduce_bbdrec.sh`, `tune_*.sh`) expose `NUM_GPUS`, `TASKS_PER_GPU`, and `GPU_START` near the top of each file — adjust them to match your hardware. To run on CPU, pass `--device cpu` to `main.py`.

### Hardware We Used

All numbers reported in the paper were obtained on a **single NVIDIA RTX 4090 (24 GB)** per run, with all experiments executed under the following setup:

| Resource | Value |
|----------|-------|
| GPU      | NVIDIA RTX 4090 (24 GB VRAM, CUDA 12.1) |
| CPU      | Intel(R) Xeon(R) Platinum 8336C @ 2.30 GHz |
| RAM      | ≥ 64 GB |
| OS       | Ubuntu 22.04 LTS |
| PyTorch  | 2.1.2 (cu121) |

The largest dataset (Yelp, ≈ 64K items, 1.6M interactions) fits comfortably in 24 GB at the default `hidden_size=128`, `max_len=50`, `batch_size=512`. Training BBDRec to convergence (with early stopping `patience=4`, `eval_interval=5`) takes:

| Dataset  | Wall-clock on 1× RTX 4090 |
|----------|---------------------------|
| ML-100K  | ≈ 5 min |
| Baby     | ≈ 8 min |
| Toys     | ≈ 10 min |
| Beauty   | ≈ 12 min |
| Sports   | ≈ 18 min |
| Yelp     | ≈ 40 min |

The multi-GPU launchers scale linearly with the number of cards: e.g. `reproduce_bbdrec.sh` on 6× RTX 4090 (one dataset per card, `TASKS_PER_GPU=1`) finishes the entire 6-dataset paper-best reproduction in ≈ 40 min wall-clock.

The full hyperparameter sweep (`tune_bbdrec_ds_vm_ls.sh`, 5×5×4 = 100 combos × 6 datasets = 600 runs) was distributed across 4× RTX 4090 with `TASKS_PER_GPU=1`, completing in ≈ 24 h on Yelp and ≪ 8 h on the smaller datasets. Adjust `NUM_GPUS` / `TASKS_PER_GPU` according to your fleet — these scripts are designed to oversubscribe cards safely as long as memory allows.

## Datasets

| Dataset  | #Items | #Interactions | Source |
|----------|-------:|--------------:|--------|
| ML-100K  | 1,008  | ≈ 100K        | MovieLens 100K |
| Beauty   | 6,086  | ≈ 0.2M        | Amazon Review |
| Toys     | 7,309  | ≈ 0.4M        | Amazon Review |
| Baby     | 4,731  | ≈ 0.5M        | Amazon Review |
| Sports   | 12,301 | ≈ 1.5M        | Amazon Review |
| Yelp     | 64,669 | ≈ 1.6M        | Yelp Challenge |

Each dataset lives at `datasets/data/<name>/dataset.pkl` and is a pickled dict with keys `train`, `val`, `test`. Each value is a `dict[user_id] -> list[item_id]` of chronologically ordered items (item ids start at 1, with 0 reserved for padding). The loaders in `src/utils/data.py` left-pad sequences to `max_len=50` and produce both:

- `parallel_ag=True`  → next-item target at every position (autoregressive training, default for BBDRec / SASRec / GRU4Rec / FEARec / EulerFormer / SVAE).
- `parallel_ag=False` → single target at the last position (used by BERT4Rec, CORE, LightSANs, DiffuRec, DreamRec).

Item counts per dataset are hard-coded in `core/trainer.py::item_num_create`. If you add a new dataset, register it there and drop its `dataset.pkl` under `datasets/data/`.

## Quick Start — Reproduce BBDRec

```bash
cd src

# 1. (Optional) Train SASRec to obtain pretrained item embeddings.
#    Pre-trained checkpoints are already shipped under saved/pretrain/<dataset>/.
python main.py --model pretrain --dataset ml-100k --description sasrec_pretrain

# 2. Train BBDRec with paper-best hyperparameters on a single dataset.
python main.py --model bbdrec --dataset ml-100k \
    --diffusion_steps 4 --var_max 0.5 --loss_scale 10 \
    --description bbdrec_ml-100k_best

# 3. Reproduce all 6 datasets with the paper-best (ds, vm, ls) tuples.
bash reproduce_bbdrec.sh
```

The paper-best hyperparameters per dataset (encoded in `reproduce_bbdrec.sh`):

| Dataset  | diffusion\_steps | var\_max | loss\_scale |
|----------|-----------------:|---------:|------------:|
| ML-100K  | 4  | 0.5 | 10   |
| Beauty   | 8  | 0.5 | 1    |
| Toys     | 16 | 4   | 1    |
| Baby     | 2  | 4   | 1    |
| Sports   | 2  | 0.5 | 0.01 |
| Yelp     | 2  | 4   | 0.1  |

Logs and final test metrics are written to `logs/reproduce_bbdrec/<model>_<dataset>.log`; a tabular summary appears at the end of `reproduce_bbdrec.log`.

## Our Methods

| Variant     | Description                                                                                       |
|-------------|---------------------------------------------------------------------------------------------------|
| `bbdrec`    | **Main model.** Brownian-bridge diffusion + pretrained item embeddings + 5-epoch frozen warm-up. |
| `bbdrec-0`  | Ablation: no pretraining (random item embeddings).                                                |
| `bbdrec-1`  | Ablation: pretraining without the frozen warm-up phase.                                           |
| `pretrain`  | A SASRec used solely to dump item embeddings to `saved/pretrain/<dataset>/pretrain.pth`.          |

Run any variant with `python main.py --model <variant> --dataset <name>`.

## Baseline Models

All baselines are ported into BBDRec's unified `(item_seq, tgt_seq)` interface. Adaptation notes (e.g. how a bidirectional model is wired into left-padded sequences) live in `core/trainer.py::choose_model`. We list the original paper and the codebase used as a reference for each port.

> **Hyperparameter settings.** Unless stated otherwise, every baseline reuses the *same* shared protocol as BBDRec — `max_len=50`, `hidden_size=128`, `dropout=0.5`, `lr=1e-3`, `batch_size=512`, Adam optimizer, HR/NDCG@{5,10,20}, early stopping `patience=4` with `eval_interval=5` — following **DiffuRec** (Li *et al.*, TOIS 2023, [arXiv:2304.00686](https://arxiv.org/abs/2304.00686)). The only model-specific knobs we keep from the original baseline papers are the architectural ones (e.g. BERT4Rec mask ratio, FEARec frequency-domain ratio, EulerFormer rotary-emb dim, SVAE KL annealing), to keep the comparison strictly fair on the *training* side.

|-----|--------|-----------|-------------|
| `diffurec` | **DiffuRec**: A Diffusion Model for Sequential Recommendation (Li *et al.*, TOIS 2023) | [paper](https://arxiv.org/abs/2304.00686) | `python main.py --model diffurec --dataset <name>` |
| `dreamrec` | **DreamRec**: Generate What You Prefer: Reshaping Sequential Recommendation via Guided Diffusion (Yang *et al.*, NeurIPS 2023) | [paper](https://arxiv.org/abs/2310.20453) · [code](https://github.com/YangZhengyi98/DreamRec) | `python main.py --model dreamrec --dataset <name>` |

### Batch training of all baselines

`src/run_baselines.sh` is a one-click launcher that trains **every** baseline above on **every** dataset, distributed across multiple GPUs. The model list and dataset list are declared at the top of the script:

```bash
# src/run_baselines.sh
MODELS=("sasrec" "gru4rec" "bert4rec" "lightsans" "core" "fearec" \
        "eulerformer" "svae" "diffurec" "dreamrec" "sdifrec")
DATASETS=("baby" "beauty" "ml-100k" "sports" "toys" "yelp")
NUM_GPUS=4           # number of GPUs to use
TASKS_PER_GPU=3      # concurrent jobs per GPU
GPU_START=0          # starting cuda index (cuda:0, cuda:1, ...)
```

Run it with:

```bash
cd src
bash run_baselines.sh
```

The launcher round-robins the 11 × 6 = 66 (model, dataset) jobs over `NUM_GPUS × TASKS_PER_GPU` workers, writes per-job logs to `logs/baselines/<model>_<dataset>.log`, and aggregates test HR@{5,10,20} / NDCG@{5,10,20} into a single table at the end of `logs/baselines/run_baselines.log` once all jobs finish.

All baselines inherit the shared training protocol from `config.yaml` (the DiffuRec setting; see the callout above), so the only thing you need to change to run an additional baseline is to append its key to `MODELS=(...)`.

## Hyperparameter Tuning

BBDRec's three primary knobs are:

| Flag | Description | Searched range (paper) |
|------|-------------|------------------------|
| `--diffusion_steps` | Number of Brownian-bridge timesteps | `{2, 4, 8, 16, 32}` |
| `--var_max` | Max variance of the bridge process | `{0.5, 1, 2, 4, 8}` |
| `--loss_scale` | Weight on the diffusion (MSE) loss | `{0.01, 0.1, 1, 10}` |

Reproduce the full grid search on a dataset:

```bash
cd src
# Edit DATASET=... at the top of the script first.
bash tune_bbdrec_ds_vm_ls.sh
```

Every run writes a log under `logs/bbdrec_<dataset>/`; the script prints a sorted leaderboard by HR@20 / NDCG@20.

Other hyperparameters (e.g. `--hidden_size`, `--dropout`, `--lr`) can be tuned the same way — any field in `config.yaml` is exposed as a CLI flag through `utils/logger.py`.

## Ablation Study

`ablation_bbdrec.sh` runs four ablations of the main BBDRec recipe per dataset:

| Variant | What is removed |
|---------|------------------|
| `no_pretrain` (`bbdrec-0`) | Random instead of pretrained item embeddings |
| `no_warmup`   (`bbdrec-1`) | Skip the 5-epoch frozen warm-up |
| `no_mse`      (`--loss_scale 0`) | Drop the diffusion MSE loss |
| `mlp_decoder` (`--diff_decoder mlp`) | Replace the Transformer denoiser with an MLP |

```bash
cd src
bash ablation_bbdrec.sh
```

Each variant is launched with the paper-best `(ds, vm, ls)` of that dataset; the script prints a per-dataset ΔHR%/ΔNDCG% table relative to the baseline.

## Adding a New Model

Every model in `src/models/` follows the same contract — copy `models/sasrec.py` as a starting template:

```python
class MyModel(nn.Module):
    def __init__(self, args): ...
    def forward(self, item_seq, tgt_seq, train_flag=True):
        # item_seq, tgt_seq: [B, max_len], left-padded with 0
        return out_seq, last_item, aux_loss          # last_item := out_seq[:, -1, :]
    def calculate_loss(self, out_seq, tgt_seq): ...  # → scalar CE
    def calculate_score(self, item):           ...   # [B, item_num+1]
```

Then:

1. Register an alias in `models/__init__.py`.
2. Add a `elif args.model == "mymodel"` branch in `core/trainer.py::choose_model`. If the model is bidirectional / sequence-to-vector, set `args.parallel_ag = False`, `args.split_onebyone = True`. If the model has an auxiliary loss (KL, contrastive, …), extend the loss assembly block in `model_train` (search for `args.model == "svae"` for an example).
3. Optionally add hyperparameters to `config.yaml` — they are auto-exposed as CLI flags.

A quick way to sanity-check a new model is to launch a 1-epoch run on `ml-100k`:

```bash
python main.py --model mymodel --dataset ml-100k --epoch_num 1
```
